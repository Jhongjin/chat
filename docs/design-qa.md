# UI/UX 디자인 점검 결과

기준일: 2026-05-30.

## 결론

초기 디자인 방향은 유지하되, 바로 구축하기 전 반드시 고쳐야 할 지점이 있었다. 이번 점검 이후 MVP 화면에는 다음 보완을 반영했다.

- 온보딩 우회 방지: 만 18세 이상 확인과 정책 동의 전에는 모달을 닫을 수 없게 했다.
- 위치 거부 fallback: 위치 권한이 없으면 실제 근처 친구처럼 보이는 더미 목록을 숨기고 빈 상태를 보여준다.
- 쪽지 요청 플로우: 쪽지 버튼을 눌러도 즉시 채팅방이 열리지 않고, 요청 대기 상태로 이동한다.
- 신고/차단 실동작: 채팅 헤더에서 신고 사유, 대화 숨김, 차단을 분리한 안전 메뉴를 제공한다.
- 빈 상태: 동네 친구 없음, 열린 대화 없음, 위치 미허용 상태를 마스코트와 CTA로 안내한다.
- 접근성: 주요 아이콘 버튼에 `accessibilityLabel`을 추가하고 터치 타깃을 44-48px 이상으로 맞췄다.
- 리워드 UX: 광고 보상은 즉시 지급이 아니라 확인 중 상태와 일일 3회 상한을 둔 구조로 바꿨다.
- 거리 표현: `1.6km` 같은 정밀 표시 대신 `500m 이내`, `약 2km`처럼 대략적으로 표시한다.
- 추천 UX: 사람 카드마다 추천 점수와 이유를 보여줘 무작위 목록처럼 느껴지지 않게 했다.
- 대화 품질: 관심사 필터, 첫 쪽지 템플릿, 빠른 답장, 연락처/주소 공유 안전 넛지를 추가했다.

## 캐릭터 방향

마스코트는 `온이`라는 내부 이름의 추상 캐릭터로 잡는다. 지도 핀, 말풍선, 작은 안심 불빛을 합친 형태이며 동물, 사람, 커플, 하트, 불꽃 이미지는 쓰지 않는다. 캐릭터는 빈 상태, 권한 안내, 안전 메뉴처럼 감정 부담을 낮추는 곳에만 제한적으로 사용한다.

## 남은 구축 과제

- 실제 인증/약관/위치 동의 저장
- Supabase 수락/거절 플로우는 연결됨. 다음 검수는 실제 기기 2대에서 Realtime 메시지 중복/지연 여부 확인
- 계정 삭제 요청은 Supabase RPC까지 연결됨. 남은 과제는 운영자 콘솔에서 보관 기간과 최종 삭제 처리를 수행하는 것
- AdMob SDK와 서버 사이드 보상 검증
- iOS/AOS 실기기 접근성 및 권한 거부 QA
